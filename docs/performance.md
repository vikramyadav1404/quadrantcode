# Query performance

> Generated by `scripts/explain-report.ts` against the integration test
> database. Every plan below is pasted output, not a description of one.

## Why the dataset is padded

Selectivity, not row count, decides a plan. On a 30-row catalog Postgres
correctly prefers a sequential scan, so an EXPLAIN there would prove
nothing about production. The fixture therefore loads ~50k problems with a
40-value topic vocabulary (3 tags each), 400 days of `daily_sessions` and
3k verification codes, which is the shape the indexes were designed for.
